# AQUA 普通角色动作核对

本记录对应 `tools/build_character_actions.py` 与生成的 `assets/character-actions.json`。素材是用户本机第五章 `data.win` 的导出结果；没有修改游戏文件。

原文件 SHA-256：`370dfd141d2955d5a1960122919b16e4092b52ffbb85fda541bc4680c6b3b85c`。

## 核对方法

读取 `ch5-all/CodeEntries` 中已经导出的 GML，检查改变图片、帧索引、速度、位置的代码。数字 sprite ID 通过 UndertaleModCli 的只读 `load --line` 遍历 `Data.Sprites` 对照名称。所有动作条目保留原始 GML 文件名和行号；行号对应本次导出的文本，而不是字符串中旧版的 `_gml_...` 行号。

`verified: true` 表示所列片段的图片、帧率或指定姿势有脚本依据。它不表示曾运行原游戏逐帧录像比对，也不表示整段剧情、所有其他人物、对白时长和背景特效均已复制。

## 已实现内容

生成器输出 **106 个普通角色预设，引用 58 组资源**。包括连续动作的场景速度版本、静态姿势、带手动继续的片段，以及有明确数值的位移动作。其余原始素材由程序的资源浏览器单独展示，攻击组合和弹幕由另一份生成器负责。

| 动作 | 原作依据与处理 |
|---|---|
| 默认晃动 | `obj_aqua_enemy_Create_0:6` 设置 `image_speed=1/6`，`scr_enemy_drawidle_generic:6` 每个 tick 加到绘制索引。8 帧各 6 tick，共 48 tick，也就是 1.6 秒。 |
| 战斗转圈、跳舞、笑 | 使用战斗的 `1/6`；脚本单独改速的兴奋 `1/3`、无聊 `1/8`、鼓掌 `1/4` 各有预设。 |
| 剧情笑与挥袖 | 笑分别保留 `1/6、0.2、0.25、0.3`；挥袖分别保留 `0.2、0.25、1/3、0.4`。没有给全部素材套同一个帧率。 |
| 转圈 | 分别保留四帧 `spr_aqua_spin` 和五帧 `spr_enemy_aqua_spin`；战斗、悬崖、牢房、流沙等使用不同速度。 |
| ACT 恭维 | `obj_aqua_enemy_Step_0:648-649` 仅把 `flattery_id` 从 4 插到 11，历时 21 tick；`Draw_0:8` 按该索引画图。因此按 4→11 播放并停留，不把 0→11 当普通循环。 |

| 绿色版本 | 依据 `force_animation` 及调用对象的 `image_speed`，包括晃动、鼓掌、无聊、兴奋、笑、旋转、托举、惊讶和摆姿势。普通 Yellow 场景速度来自 `obj_dw_fcastle_yellow_combat_Step_0:19` 的 `0.25`。 |
| 坐姿 | 分别提供射击关卡 `0.2` 和悬崖 NPC `0.25`；静态姿势不伪造播放速度。 |
| 行走 | 四方向角色图片和 actor 慢速行走下限 `0.25`；另外保留 Seth 战后上行、右行的 `1/6`。资料室向右走 240 世界像素／60 tick、战后向右走 160 世界像素／60 tick 各为完整位移片段。 |
| 原地跳跃 | 花园的两次同点跳跃分别使用 `(gravity=1.5, vspeed=-12, image_index=0→8)` 和 `(1.3,-14,0→6)`；使用原作落地时间公式，末尾等待手动继续。 |
| 升空、滑入、鼓掌跳跃 | 旋转离场保留 2→1/3 的速度变化与 120 tick 上升 480 世界像素；咖啡馆挥袖从 x338 到 x260 用 12 tick；换装鼓掌每 15 tick 重启一次原地跳。 |

## 时间和位置

- 一个 tick 是原游戏的一次更新，本项目固定 30 tick／秒。`0.4`、`0.3` 等速度用整数 tick 的长周期保存，避免把每帧时长简单四舍五入后持续变快或变慢。
- 独立预览从相位 0 开始，原作连续切换场景时可能从继承的中间帧开始。预设名称描述动作片段，不替原作决定何时触发。
- 位置保存为素材的原始像素。暗世界通常以 2 倍绘制，所以相应世界位移除以 2；例如 240 世界像素在数据中为 120 素材像素。桌宠再统一乘用户选择的显示倍率。
- 静态姿势用一个 1 tick 单元重复显示。它不是对原作停留时长的断言。
- 对话等待不会伪造秒数；以 `wait: true` 交给 Debug 的“继续”。
- 红水花的浮动函数与帧循环没有有限整数 tick 的共同周期，保存 210 tick 的原作样本后重播；该截取边界在动作说明中明确标出。

## 保留为素材的内容及限制

- `spr_enemy_aqua_idle_leftorigin`、`spr_enemy_aqua_knifespin_temp` 在原素材目录标为未使用，未编造角色预设。
- `spr_aqua_grab`、`spr_aqua_grab_hold2` 在本次全部 GML 的名字和数字 ID 搜索中没有找到使用。这个结果只说明脚本搜索没有命中，不能证明游戏所有数据对象均不引用它们；仍保留可查看素材。
- `spr_aqua_centered` 在 `obj_ch5_DW40_Step_0:341` 创建后马上切换为 `spr_flowers`，因此没有把它虚构成可见的独立动作。
- 本生成器不重建房间背景、其他角色、反射着色、镜头移动、音效、随机横向跳跃路径、战斗碰撞、整段对白及触发条件。场景中依赖房间标记坐标的完整跨人物走位未宣称已经逐帧复原。
- 各预设的脚本数值已核对，但 GameMaker 原生重力、图像更新与 Step/Draw 的先后顺序尚未通过游戏运行录像比对。离散运动起始帧可能需要这一轮运行比对后进一步校准。

## 生成和检查

运行 `python tools/build_character_actions.py`。可通过 `--code-dir` 指向另一份对应版本的 GML 导出，`--sprites` 指向素材清单，`--output` 指向输出 JSON。原作文件只读。

生成器检查动作 ID 唯一、素材存在、帧索引不越界、tick 为正、坐标有限；源码目录存在时还检查引用的文件和行号有效。另固定检查默认晃动的 48 tick 时长与 ACT 的 4..11 帧顺序。程序层的播放、暂停、循环、同步及窗口操作由 Rust 测试和桌面验收检查。
